# 면접 대비 개념 Q&A 스킬

프로젝트를 직접 읽어 사용된 기술과 설계 결정을 추출한 뒤, 면접관이 물을 법한 질문을 동적으로 생성하고 답변과 꼬리질문으로 구성한 문서를 만든다.

## 핵심 원칙

질문 목록을 사전에 고정하지 않는다. 모든 질문은 프로젝트를 읽은 후에 생성된다. 같은 스킬을 다른 프로젝트에 적용하면 다른 질문이 나와야 한다.

## Step 1: 프로젝트에서 추출할 것

`project-deep-dive.md`가 있으면 먼저 읽는다. 없으면 프로젝트 소스를 직접 탐색한다.

탐색하며 다음을 목록으로 정리한다:

**기술 스택** (사용된 모든 기술)
- 각 기술의 역할, 버전, 의존성

**설계 결정** (왜 이렇게 만들었는가)
- 특정 기술을 선택한 이유
- 특정 패턴을 사용한 이유 (예: MERGE, frozen dataclass, Stream)

**트레이드오프** (무엇을 포기했는가)
- 선택된 기술의 단점, 대체 기술과의 비교

**아키텍처 경계** (레이어 간 경계와 그 이유)
- 왜 레이어를 이렇게 나눴는가

## Step 2: 항목별 질문 생성 규칙

추출한 각 항목에 대해 아래 4가지 관점으로 질문을 생성한다:

| 관점 | 질문 유형 | 예시 |
|------|---------|------|
| **개념** | "X는 무엇인가? 주목적이 무엇인가?" | "Airflow는 무엇이고 주목적이 무엇인가?" |
| **선택 이유** | "왜 이 프로젝트에서 X를 썼는가?" | "왜 Kafka 대신 Snowflake Stream을 썼는가?" |
| **트레이드오프** | "X를 쓰면 무엇을 포기하는가?" | "Snowflake Stream이 Kafka CDC를 완전히 대체할 수 있는가?" |
| **대안 비교** | "X 대신 Y를 쓰면 어떻게 다른가?" | "Airflow 대신 GitHub Actions를 쓰면 무엇이 달라지는가?" |

모든 항목에 4가지 관점을 다 적용할 필요는 없다. 해당 기술에서 면접관이 실제로 물을 법한 관점만 선택한다.

## Step 3: Q&A 작성 형식

각 질문을 다음 형식으로 작성한다:

```markdown
### Q. {질문}

**A.** {답변}
- 핵심 개념 설명
- 이 프로젝트에서의 구체적 사용 사례
- 선택 이유 또는 트레이드오프

**꼬리질문 1.** {더 깊은 질문}
> {꼬리 답변}

**꼬리질문 2.** {다른 각도의 질문}
> {꼬리 답변}

**꼬리질문 3.** {실무/트레이드오프 관련 질문}
> {꼬리 답변}
```

꼬리질문은 이렇게 설계한다:
- **꼬리질문 1**: 개념을 더 깊게 파고드는 질문 (내부 동작 원리)
- **꼬리질문 2**: 다른 기술과의 비교 또는 대안 질문
- **꼬리질문 3**: 실무 트레이드오프 또는 장단점 질문

## Step 4: 산출물 구조 (`interview-concepts.md`)

```markdown
# {프로젝트명} 면접 대비 개념 Q&A

## 목차
1. {기술/주제 1}
2. {기술/주제 2}
...

---

## 1. {기술/주제}
> 이 프로젝트에서의 역할: {한 줄 요약}

### Q. ...
(Q&A 형식)

---
```

기술을 묶는 방식:
- 관련 기술끼리 섹션으로 묶는다 (예: "데이터 적재 레이어", "오케스트레이션", "시각화")
- 섹션 상단에 "이 프로젝트에서의 역할"을 한 줄로 요약한다

## Step 5: 깊이 기준

답변의 깊이는 다음 수준을 목표로 한다:
- 개념 설명: 모르는 사람도 이해할 수 있는 수준
- 선택 이유: 이 프로젝트의 구체적 맥락을 포함
- 꼬리질문 답변: 실제 면접에서 "잘 아시네요"를 들을 수 있는 수준

## 후속 실행 처리

`interview-concepts.md`가 이미 존재하면:
- "X 섹션 보완" → 해당 섹션만 업데이트
- "꼬리질문 추가" → 기존 Q&A에 꼬리질문 보강
- 전체 재생성 → 기존 파일을 `interview-concepts_{YYYYMMDD}.md`로 보관 후 새로 생성
